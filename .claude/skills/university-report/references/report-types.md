# هياكل التقارير الجامعية

هذه هياكل شائعة، لا قوانين. **ما يطلبه التكليف أو قالب القسم يتقدم دائماً.** والنسب تقريبية من جسم التقرير، أي بدون الغلاف والمراجع والملاحق.

كل تقرير، أياً كان نوعه، يبدأ عادةً بالغلاف، ثم الملخص (إن طُلب)، ثم المحتويات، وينتهي بالمراجع ثم الملاحق.

---

## 1. التقرير البحثي / الورقة الفصلية (Research report / term paper)

| القسم | ما فيه | النسبة |
|---|---|---|
| الملخص (Abstract) | الهدف، والمنهج، وأهم النتائج، والخلاصة في 150–250 كلمة | — |
| المقدمة (Introduction) | خلفية من العام إلى الخاص، ثم المشكلة، والأسئلة أو الأهداف، والأهمية، وحدود الدراسة، وخريطة التقرير في جملة أو اثنتين | 10–15% |
| الإطار النظري والدراسات السابقة (Literature review) | منظَّم **حسب المحاور**: أين تتفق الدراسات، وأين تختلف، وما الفجوة التي يعالجها التقرير | 25–35% |
| المنهجية (Methodology) | نوع الدراسة، ومصادر البيانات، والأدوات، والعينة، والإجراءات، وطريقة التحليل | 10–15% |
| النتائج والمناقشة (Results & discussion) | النتيجة، ثم تفسيرها، ثم مقارنتها بالدراسات السابقة | 30–40% |
| الخاتمة والتوصيات (Conclusion) | إجابة كل سؤال، وتوصيات مبنية على النتائج، والحدود، ومقترحات لبحوث لاحقة | 5–10% |

**أخطاء شائعة:** مراجعة أدبيات مرتبة مرجعاً مرجعاً («قال فلان… وقال فلان…») بلا تركيب · خاتمة فيها معلومات جديدة · أسئلة في المقدمة لا تُجاب في الخاتمة.

> **ورقة بلا جمع بيانات** (مقالة بحثية مكتبية): تُستبدل المنهجية بفقرة «منهج التقرير» (كيف اختيرت المصادر وحُللت)، وتصير «النتائج والمناقشة» أقساماً موضوعية، لكل محور قسم.

## 2. تقرير المختبر (Lab report)

| القسم | ما فيه |
|---|---|
| العنوان | يذكر ما قيس وبأي طريقة |
| الملخص | الهدف، والطريقة، والنتيجة الرقمية الرئيسية مع خطئها، والخلاصة |
| المقدمة | النظرية والمعادلات، والهدف، والفرضية |
| الأدوات والطريقة (Materials & methods) | الأدوات بدقتها، والخطوات **بالماضي** وبصيغة المبني للمجهول عادةً («قيست…»، "was measured")، بتفصيل يسمح بتكرار التجربة. لا تنسخ ورقة التعليمات حرفياً |
| النتائج (Results) | جداول البيانات بالوحدات، والرسوم البيانية بمحاور معنونة، ومثال حسابي واحد. **بلا تفسير** |
| المناقشة (Discussion) | هل تحققت الفرضية؟ والمقارنة بالقيمة النظرية، وتحليل الخطأ (Error analysis)، ومصادر الخطأ المحددة (لا «خطأ بشري» عامة)، واقتراحات التحسين |
| الخاتمة | نتيجة رقمية واحدة أو اثنتان، والإجابة عن الهدف |
| الملاحق | البيانات الخام، والحسابات الكاملة |

**تحليل الخطأ:** نسبة الخطأ = |القيمة التجريبية − القيمة النظرية| ÷ القيمة النظرية × 100%. اذكر الشك (uncertainty) مع كل قياس إن طُلب، وبعدد أرقام معنوية (significant figures) متسق.

**البيانات من الطالب فقط.** لا تولّد قياسات «معقولة» أبداً. إن لم تصل البيانات، فاكتب الهيكل وعلامات `[بيانات مطلوبة]`.

## 3. التقرير التقني أو الهندسي (Technical report)

| القسم | ما فيه |
|---|---|
| الملخص التنفيذي (Executive summary) | يُقرأ وحده: المشكلة، والحل، والنتائج، والتوصية |
| المقدمة | السياق، والمتطلبات، والنطاق |
| الخلفية النظرية | المبادئ والمعايير (Standards) ذات الصلة |
| التصميم أو المنهجية | البدائل التي دُرست، ومعايير الاختيار، والتصميم المختار ومبرره |
| التنفيذ والنتائج | ما بُني أو حُسب، والاختبارات، والأرقام |
| المناقشة | هل حقق التصميم المتطلبات؟ والقيود، والمخاطر، والتكلفة |
| الاستنتاجات والتوصيات | مرقمة وقابلة للتنفيذ |
| الملاحق | الحسابات، والمخططات، والشيفرة، وأوراق المواصفات |

**مفيد هنا:** جدول مقارنة البدائل (Decision matrix) بمعايير موزونة، يبرر الاختيار بدلاً من وصفه فقط.

## 4. دراسة الحالة (Case study)

| القسم | ما فيه |
|---|---|
| الملخص التنفيذي | المشكلة والتوصية في فقرة |
| المقدمة | الغرض والنطاق |
| خلفية الحالة | الحقائق الضرورية فقط، لا إعادة سرد الحالة كلها |
| تحديد المشكلة | المشكلة الجوهرية لا أعراضها، مع الأدلة من الحالة |
| التحليل | بإطار مناسب: SWOT، أو PESTLE، أو قوى بورتر الخمس (Porter's Five Forces)، أو سلسلة القيمة، أو إطار من المقرر نفسه. **الإطار أداة لا هدف**: كل خانة تنتهي بـ«وهذا يعني…» |
| البدائل | 2–3 حلول، ولكل منها مزاياه وعيوبه ومعايير المفاضلة |
| التوصية وخطة التنفيذ | الحل المختار، ولماذا، ومن يفعل ماذا ومتى، ومؤشرات النجاح |
| الخاتمة | — |

**أخطاء شائعة:** تلخيص الحالة بدل تحليلها · تحليل SWOT قائمة بلا استنتاج · توصية لا تنبع من التحليل.

## 5. تقرير الأعمال (Business report)

الملخص التنفيذي ← المقدمة (الغرض، والنطاق، والمنهج) ← النتائج (Findings) ← التحليل ← الاستنتاجات ← التوصيات (مرقمة، وقابلة للقياس، ومرتبة حسب الأولوية) ← المراجع ← الملاحق.

العناوين هنا **وصفية** («انخفاض المبيعات في الربع الثالث»)، لا عامة («النتائج»). والقارئ مدير مشغول: الخلاصة أولاً، والتفاصيل بعدها.

---

## 6. تقرير التدريب الميداني / العملي (Internship / practical training report)

شائع في الجامعات العربية، وكثيراً ما يكون للقسم نموذج خاص به. اسأل عنه أولاً.

| القسم | ما فيه |
|---|---|
| الإقرار (Declaration) | إن طلبه القسم |
| الشكر والتقدير | لجهة التدريب والمشرفين، بأسمائهم كما يعطيها الطالب |
| الملخص | الجهة، والمدة، وأبرز المهام والمكتسبات |
| المقدمة | أهداف التدريب، وأهميته للتخصص |
| نبذة عن جهة التدريب | النشاط، والرؤية والرسالة، والهيكل التنظيمي، والقسم الذي تدرّب فيه الطالب. المعلومات العامة من موقع الجهة الرسمي، **موثّقة** |
| المهام والأنشطة | أسبوعياً أو حسب المشروع: ماذا فعل، وبأي أدوات، وما الناتج |
| المهارات المكتسبة | تقنية وشخصية، **وربطها بمقررات درسها** |
| التحديات والحلول | موقف محدد ← ما فعله ← ما تعلمه |
| التقييم الذاتي والتوصيات | للجهة، وللقسم، وللطلاب القادمين |
| الخاتمة | — |
| الملاحق | سجل الحضور، ونماذج من العمل (بعد إذن الجهة)، وشهادة التدريب |

**هذا التقرير يقيس تجربة الطالب نفسه.** اطلب منه سجلاً أسبوعياً، ولو نقاطاً مختصرة: ماذا فعلت؟ وما الأداة؟ وما الذي صعب عليك؟ وما الذي تعلمته؟ ثم صُغه أنت. لا تخترع مهمة أو موقفاً لم يحدث، واستعمل `[من تجربتك: …]` لكل فجوة.

**السرية:** لا تُدرج بيانات داخلية للجهة، أو أسماء عملاء، أو لقطات شاشة لأنظمتها، إلا بإذن.

## 7. تقرير مشروع التخرج (Capstone / graduation project)

**الصفحات التمهيدية:** الغلاف، وصفحة الإجازة أو اعتماد اللجنة، والإقرار، والإهداء (اختياري)، والشكر، والملخص بالعربية **وبالإنجليزية** (كثيراً ما يُطلب الاثنان)، والمحتويات، وقوائم الأشكال والجداول والمختصرات.

| الفصل | ما فيه |
|---|---|
| 1. المقدمة | المشكلة، والدافع، والأهداف (قابلة للقياس)، والنطاق والحدود، والأهمية، وتنظيم التقرير |
| 2. الدراسات السابقة أو الأعمال المشابهة (Related work) | ما الموجود؟ وجدول مقارنة بالحلول المشابهة، وموقع المشروع منها |
| 3. المنهجية أو التحليل | منهجية العمل (Agile أو Waterfall…)، والمتطلبات الوظيفية وغير الوظيفية. وفي تقنية المعلومات: حالات الاستخدام (Use cases) ومخططات UML |
| 4. التصميم والتنفيذ | البنية (Architecture)، وقاعدة البيانات، والواجهات، والأدوات ومبرر اختيارها |
| 5. الاختبار والنتائج | خطة الاختبار، وحالاته، ونتائجه، ومقارنتها بالأهداف |
| 6. الخاتمة والعمل المستقبلي | ما تحقق مقابل كل هدف، والقيود، والتطوير المقترح |
| المراجع والملاحق | الشيفرة المختصرة، ودليل المستخدم، والاستبانات |

**التقرير الطويل يحتاج اتساقاً:** ثبّت في `outline.md` أسماء المكونات، والاختصارات، والأرقام، ونسخ الأدوات، وارجع إليها في كل فصل. اكتب فصلاً واحداً في كل جلسة، وراجعه قبل الانتقال إلى التالي.

---

## 8. مراجعة الأدبيات (Literature review)

- **التنظيم:** حسب المحاور (الأكثر شيوعاً)، أو زمنياً (لتتبع تطور فكرة)، أو حسب المنهج.
- **أداة التركيب:** مصفوفة (Synthesis matrix) صفوفها المصادر وأعمدتها المحاور. منها تُكتب فقرات المحاور، فلا تتحول المراجعة إلى تلخيص مرجع بعد مرجع.
- **كل فقرة:** جملة تعلن المحور ← ما تتفق عليه المصادر ← أين تختلف ولماذا ← ما الذي لم يُدرس بعد.
- **الخاتمة:** الفجوة البحثية بوضوح، وكيف تبرر السؤال.

---

## 9. التقرير التأملي (Reflective report)

إطار شائع: **دورة جيبس التأملية (Gibbs' Reflective Cycle, 1988)**، وتتكون من ست مراحل:

| المرحلة | السؤال |
|---|---|
| الوصف (Description) | ماذا حدث؟ |
| المشاعر (Feelings) | بماذا شعرت وفكرت حينها؟ |
| التقييم (Evaluation) | ما الذي سار جيداً، وما الذي لم يسر؟ |
| التحليل (Analysis) | لماذا؟ وهنا يُربط الموقف بالنظرية أو بالمقرر، **مع التوثيق** |
| الاستنتاج (Conclusion) | ماذا كان يمكن أن أفعل بطريقة مختلفة؟ |
| خطة العمل (Action plan) | ماذا سأفعل في المرة القادمة؟ |

يُكتب بضمير المتكلم عادةً. **المادة كلها من الطالب.** اسأله عن الموقف بالتفصيل، ثم ساعده في الصياغة والربط بالنظرية. لا تكتب مشاعر لم يذكرها.

---

## 10. تقرير الزيارة الميدانية (Field visit report)

المقدمة (الجهة، والتاريخ، والهدف من الزيارة) ← وصف ما شوهد (العمليات، والأقسام، والأنظمة) ← الربط بالمقرر (أين ظهرت المفاهيم التي درسها الطالب؟) ← الملاحظات النقدية ← التوصيات ← الخاتمة. الصور تُدرج فقط بإذن الجهة.
